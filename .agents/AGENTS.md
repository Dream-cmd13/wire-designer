# Wire Harness Designer — 代码变更记录与提交规则

## 提交范围规则
- **常规“提交”**：如果当前有上下文，默认仅提交当前上下文修改的部分文件，不管工作区中其他修改的代码（必须保留在工作区，除非改动在同一份文件）。严禁使用全量暂存（如 `git add .` 或 `git add -A`）。
- **“提交全部 / 提交所有”**：仅在用户明确说明“提交全部”或“提交所有”时，才将工作区所有修改统一总结后全量提交。

## 提交消息规则
每次修改完代码后在回复的最后面加上建议的提交消息
所有提交消息使用 Conventional Commits 格式：

```
<type>(<scope>): <简短描述>
```

| type | 说明 |
|------|------|
| feat | 新功能 |
| fix | Bug 修复 |
| refactor | 重构，不改变外部行为 |
| types | 仅修改类型定义 |
| style | 仅 UI 样式调整 |
| chore | 构建、配置、工具变更 |

scope 使用受影响的主要文件/模块名，如 `canvas`、`store`、`types`、`dialog`。
