## 五、审查后补充修复（第二轮）

- 恢复项目草稿时携带草稿原始 `baseServerRevision`：云端版本已前进时保存会被数据库拒绝并进入冲突处理；基线不可确认的旧格式草稿直接进入人工冲突处理，不再沿用云端最新版本静默覆盖。
- 丢弃旧格式（v1）草稿只删除该候选，不再连带删除同文档其他窗口的 v2 草稿。
- 写入新草稿不再顺带删除尚未处理的 v1 草稿；只有用户明确恢复或丢弃后才清理。
- 图纸云端删除与版本冲突同样暂停自动保存，并显示“云端图纸已删除/保存冲突”恢复入口（下载本地副本、读取云端版本、另存为新图纸）。
- 成本来源路径在同步/导入/上传/核对脚本间统一为内容哈希版本路径；导入与种子生成只在对象已确认存在时写入新地址，未确认时保留既有定位，避免“同步后再次导入”改回旧路径或引用不存在的对象。

对应回归测试：`projectSaveLifecycle.test.tsx`（草稿恢复基线、旧格式草稿人工冲突）、`workspaceDraftCache.test.ts`（legacy 候选删除、其他窗口草稿保留、写入不清旧草稿）、`drawingStoreAutosave.test.ts`（云端删除暂停与草稿保留、未知基线草稿暂停且不复活已删除 ID、手动保存冲突/删除必须拒绝）、`costAnalysisSync.test.mjs`（未验证不覆盖来源定位、来源状态判定）、`import-cost-analyses.test.mjs`（统一路径规则、保留既有定位、PGlite 验证离线种子只填补空值/已验证可替换/同步后重跑种子不回退）。

## 五之二、审查后补充修复（第三轮）

- 离线种子 SQL 按来源状态分组生成：已验证的版本路径允许替换；未验证的历史定位只填补空值，不再通过 `coalesce(excluded, existing)` 覆盖数据库较新的来源地址。
- 未知基线（legacy）图纸草稿恢复时暂停自动保存并进入人工恢复（`kind: 'unconfirmed'`），不会以原 ID 重新创建已删除图纸；只有用户明确“另存为新图纸”才生成新 ID。
- 图纸手动保存（含切换账号前的保存）在首次发生 conflict/missing 时明确拒绝 Promise，上层不会误判成功继续退出。
- `verify-cost-analyses.mjs` 在有服务端密钥时通过 Storage 只读确认统一版本对象是否存在：对象已存在但数据库仍引用旧定位会被判为问题；无凭据时仅提示“未验证的历史引用”，不再把路径回退当作通过。

### 已修复并补充回归

- **多窗口草稿隔离**：不再把可被同源新窗口复制的 sessionStorage ID 用作实例身份。每次页面运行生成独立 ID；刷新前和旧窗口的草稿继续保留为恢复候选。新增克隆 sessionStorage、独立写入、单窗口清理和刷新保留测试。真实 headless Chromium 的同源 opener 验证：保存前 2 份草稿，父窗口清理后仍保留子窗口草稿。
- **图纸另存完成状态**：新副本先备份，再等待云端写入确认；页面只有成功完成后提示“已另存”。网络与权限失败保留副本及草稿并显示失败，可手动重试。新增延迟保存、网络失败、权限拒绝测试。
- **成本来源不可覆盖**：解析和上传均对实际读取的字节核验大小和 SHA-256；预检后发生变化立即中止。上传使用 `upsert: false`，冲突时下载并验证已有对象与本次内容一致才可复用。单独上传脚本共用该规则。
- **部分上传失败恢复**：上传和数据库两个阶段由同一失败处理覆盖；失败报告所有已尝试路径，包括网络结果不确定的当前对象。保留对象，提示数据库引用状态未确认，不误报全部事务回滚或对象未被引用。数据库配置在首次远程写入前校验。
- **失效的冲突读取结果**：项目读取云端恢复时核对会话、账号、角色、项目和本地快照，退出登录、权限撤销或读取期间继续编辑后，旧结果不再替换当前内容。新增三类真实 React 生命周期测试。
- **成本脚本静态检查**：明确为本轮涉及的 MJS 入口、helper 和测试启用 Node ESLint 规则，清理实际检出的未使用变量和冗余正则转义；不关闭检查规则。
