# 配置向导生成图纸物料表边界与线色设计

## 背景

配置向导确认生成独立图纸后，左下角物料表会追加配置得到的物料行。当前生成逻辑只更新了 `rows`，没有同步更新表格总高度和顶部位置。由于物料表的默认底边已经贴在图框内边界，新增的表头和数据行会继续向下渲染，超出图框。

同时，独立绘图画布将表头分隔线渲染为深色、数据行分隔线渲染为灰色，Canvas 导出和旧版预览又有各自的线色来源，导致表格线视觉不统一。

## 目标

- 配置向导生成物料表后，保持表格底边位于图框内边界内侧不变。
- 物料行增加时，表格整体向上扩展，原有表头行随表格一起上移。
- 表格总高度、行高和渲染网格保持一致，避免编辑、选中和导出时出现溢出。
- 独立画布、Canvas 导出和旧版预览中的表格边框与内部网格线统一为 `#181818`。
- 仅统一表格线色，不改变普通元件、线束或用户自定义图形的线色。

## 非目标

- 不改变表格列宽、字体、字号或现有物料排序。
- 不实现物料表分页、自动缩小字体或跨图框换页。
- 不移动用户手动拖拽过的表格；只在配置向导生成物料表时重新计算其初始几何位置。
- 不改变独立图纸以外的业务数据和数据库结构。

## 方案

### 1. 生成阶段计算可变高度并固定底边

在 `createDrawingFromWizard` 生成物料表行后，使用现有表格布局规则为每条物料行生成默认行高，并计算：

```text
tableHeight = headerRowHeight + sum(rowHeights)
tableY = pageHeight - pageInset - tableHeight
```

物料表目前不显示标题行，因此计算中不额外加入标题行高度；如果未来该表启用标题行，计算应复用通用布局结果而不是写死当前数值。这样无论物料行数量如何变化，底边都固定在 `page.height - DRAWING_PAGE_INSET`，表头和数据行都会向上移动。

### 2. 表格使用专用统一线色

增加表格线色常量 `#181818`，在各表格渲染入口统一使用：

- `StandaloneDrawingCanvas`：表格外框、标题行、表头行和数据行边线使用同一颜色。
- `drawingRenderer`：绘制表格前将 Canvas 的表格描边颜色设置为同一颜色，确保导出结果与编辑画布一致。
- `DrawingCanvas`：旧版生产图纸预览中物料表和接线表的外框、列线、行线统一使用同一颜色。

普通绘图对象继续使用自身 `style.stroke`，不通过修改全局默认对象样式来影响其他图形。

## 数据流与组件边界

```text
配置向导确认
  -> createDrawingFromWizard
  -> drawingBomRows 生成物料行
  -> 计算 rowHeights / height / y（底边锚定）
  -> DrawingDocument 持久化
  -> StandaloneDrawingCanvas 编辑显示
  -> drawingRenderer Canvas 导出
```

几何修复放在生成源头，避免只在 CSS 或单个渲染器中遮盖错误数据。线色修复放在所有表格渲染器，保证已存在的表格即使存有旧样式，也能在不同显示出口保持一致。

## 测试与验收

### 自动化测试

- 扩展独立绘图生成器测试：使用多条物料的向导草稿，断言物料表的 `rows.length`、`rowHeights.length`、总高度和顶部位置；并断言 `y + height === page.height - DRAWING_PAGE_INSET`。
- 保留现有表格布局测试，确认最小行高和既有表格解析行为不变。
- 增加表格线色相关断言，覆盖独立画布和 Canvas 渲染使用的统一常量/样式。
- 运行完整 Vitest、TypeScript 构建和 ESLint。

### 手动验收

1. 打开独立绘图配置向导，生成包含多种物料的图纸。
2. 检查左下角物料表底边仍在图框内，新增行从表头上方方向扩展，不越出图框。
3. 检查物料表与接线表的外框、表头线、列线和数据行线均为 `#181818`，编辑预览与导出图一致。
4. 拖动或选中表格，确认修复未影响表格交互。

## 风险与处理

- 旧数据可能没有 `rowHeights` 或保存了旧线色：继续通过 `resolveDrawingTableLayout` 提供默认行高，并在渲染器统一覆盖表格线色，不要求迁移数据库数据。
- 物料行数量未来继续增长时，表格可能接近图框上边界：本次保持现有字号和单页模型，不引入分页；测试只保证底边锚定和当前生成范围内不溢出。
- 工作区已有与本任务无关的数据库改动：实施时只修改本设计涉及的前端文件和测试文件，不覆盖或整理其他未提交改动。
