# 报价交期固定为 7 日实施方案

## 1. 目标

当前阶段所有报价统一显示交期为 **7 日**。交期暂不参与价格计算，后续可在不改变报价核心模型的情况下切换为可配置规则。

## 2. 当前现状

- `HarnessConfig` 已存在 `leadTime` 字段。
- 交期选项目前定义在 `src/data/catalogOptions.ts`。
- 报价计算逻辑不会根据交期调整价格。
- 报价弹窗和 Excel 导出目前没有展示交期。
- 当前需求不需要新增或修改数据库表结构。

## 3. 推荐实现

新增统一的前端常量，例如：

```ts
export const DEFAULT_QUOTE_LEAD_TIME = '7日';
```

页面和导出逻辑都引用该常量：

1. 在报价弹窗的总价区域显示“交期：7日”。
2. 在报价 Excel 中增加“交期”列，值为“7日”。
3. 暂不新增交期选择器，避免用户选择与当前统一规则冲突。
4. 暂不让交期影响单价、总价或报价计算结果。
5. 保留现有 `leadTime` 字段和校验结构，避免无必要的数据模型调整；报价展示以统一常量为准。

## 4. 数据库方案

本次不修改数据库表结构，理由如下：

- 当前报价为前端估算结果，交期只是展示信息。
- 没有要求保存每次报价生成时的交期快照。
- 项目处于测试阶段，暂不需要历史报价审计或多客户交期管理。

未来若需要保存历史报价交期，应在报价记录表增加交期快照字段，例如 `lead_time_days` 或 `lead_time_text`，并在生成报价时写入，而不是实时读取当前规则。

## 5. 验收标准

- 新建报价显示“交期：7日”。
- 重新打开已有报价时显示“交期：7日”。
- 导出的报价 Excel 包含“交期”列，值为“7日”。
- 页面和 Excel 使用同一配置来源。
- 调整交期常量后，页面和 Excel 能同步变化。
- 交期变化不影响单价和订单总价。
- 相关单元测试通过。

## 6. 后续扩展

当业务需要区分加急、标准、经济等交期时，再将常量替换为目录或后台配置，并在报价生成时保存交期快照，以保证历史报价内容稳定。

## 7. 实施范围

预计涉及：

- 报价配置常量文件（新增或现有配置文件）。
- `QuotePanel` 报价展示。
- `quoteExport` Excel 导出。
- 对应报价展示和导出测试。

不涉及：

- 数据库表结构和迁移。
- 价格计算公式。
- 报价金额和成本规则。
