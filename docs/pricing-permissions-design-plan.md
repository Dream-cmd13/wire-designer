# 报价、价格明细与定价维护权限方案

日期：2026-10-10
状态：已在 `codex/pricing-permissions` 分支实施；远程数据库 SQL 和报价函数尚未部署，远程权限尚未生效。

## 一、目标与范围

业务员填写产品规格、数量等业务信息后获取最终对外报价；材料单价、成本、工时费用、损耗、毛利及价格推导过程仅供工程师、管理员查看。

工程师与管理员均允许导入、修改物料价格和定价参数。只有管理员可以分配用户角色。

业务员仅显示并访问“自动报价”tab。直接访问首页、设计器、制图、DWG、物料库等地址时切换至自动报价；角色尚未加载时同样拒绝内部页面。工程师、管理员保留完整导航。

权限必须在服务端、数据库和文件存储层生效，不能仅通过前端隐藏按钮实现。业务员浏览器不接收内部成本与推导数据。

本项目规模较小，采用三个固定角色和固定权限映射，不建设动态角色、逐用户授权或通用权限配置平台。项目处于测试阶段，直接实现目标结构，不增加兼容层、双写或过渡方案。

“能查看成本”与“能查看其他人的项目”是独立边界。保留现有项目、图纸的所有者隔离；本方案不授予工程师或管理员跨用户项目访问权。

## 四、用户角色与可信授权

1. 新增 `user_roles` 表：`user_id` 关联 `auth.users`，作为主键；`role` 仅允许 `sales / engineer / admin`，并记录更新时间和修改人。每个用户一个角色。
2. 已认证用户只可读取自己的角色，管理员通过受保护接口分配角色；客户端不得直接插入、修改或删除角色记录。
3. 数据库权限函数根据 `auth.uid()` 查询角色；服务端每次敏感操作读取当前数据库角色，不仅依赖 JWT 中缓存的角色。
4. 权限函数如使用 `SECURITY DEFINER`，固定安全的 `search_path`、限定执行授权；角色管理接口必须校验调用者当前为管理员。
5. 不用用户名、前端状态或用户自己可修改的 `user_metadata` 决定权限。用户角色缺失、读取失败或权限尚未就绪时，拒绝敏感访问和正式报价，不自动成为工程师或管理员。
6. 新建账号默认赋予业务员角色。首个管理员通过受控后台脚本指定准确用户 ID 初始化，不开放“第一个登录者成为管理员”的接口。

## 五、服务端报价与响应边界

使用 Supabase Edge Function 承接报价。将当前计算逻辑迁至服务端作为唯一实现，前端只保留格式化和展示逻辑；敏感公式与默认定价参数不得继续打包到浏览器。

### 普通报价接口

- 接收目录物料 ID、线长、数量、选定加工条件等业务输入，校验用户身份与角色。
- 根据物料 ID 重新读取真实规格与价格，校验支持范围、加工条件和输入之间的一致性；不信任客户端传入的采购价、工时单价、成本、毛利或计算结果。
- 对所有角色返回最小报价结果：状态、产品规格摘要、数量、最终含税含运费单价、总价及必要的有效性说明。
- 缺价、输入无效、不支持自动报价或需要人工核价时，返回业务可理解的状态；错误信息不包含 SQL、内部费用或公式参数。

### 内部明细接口

- 仅工程师、管理员可调用，返回材料、人工、损耗、成本、毛利、运费和完整推导过程。
- 页面需要同时显示报价和明细时，授权响应包含同一次计算的最终金额与明细，避免分别计算造成价格不一致。
- 服务端使用一份一致的价格及参数读取结果完成核价；不逐项读取期间可能变化的配置。页面展示、复制和导出使用这份结果，不在导出时重新核价。
- 价格维护后影响后续核价。已有页面报价属于计算时结果，输入变化或主动刷新时重新请求；失败或失效时清除正式金额，不使用旧报价兜底。

Edge Function 如使用服务端密钥读取受保护数据，必须先完成身份与权限校验。服务端密钥不得进入前端环境变量、浏览器响应或日志。

## 六、价格与定价参数维护

`material_prices` 继续作为唯一共享物料价格表，不建立第二套价格库。工程师、管理员可读取、导入和修改；业务员不能直接读取或写入。

新增单例 `pricing_settings` 配置表，用于保存现有计算所需的加工费、材料损耗率、加工损耗率、目标毛利率和运费率。配置应有明确字段或受约束的结构、更新时间、修改人及版本号，不允许编辑任意代码或公式字符串。

- 初始配置保持当前计算器参数及精度、舍入规则，权限改造不改变业务金额。
- 对每个字段定义数值范围，例如加工费非负、目标毛利率大于等于 0 且小于 1；损耗率、运费率采用统一的小数表示并限定范围。
- 工程师和管理员均可维护全部上述参数；业务员不读取参数值，也不提交参数覆盖值。
- 导入在服务端校验必填字段、重复键、物料关联、长度档位、价格精度和行数；整批校验成功后在同一事务提交，失败不留下部分更新。
- 参数更新携带版本号，版本冲突提示重新加载，避免两名维护人员静默覆盖。成功后刷新内部价格与配置缓存。
- 记录本次价格维护的修改人和时间；默认不增加完整历史报价或审批系统。

实施前核对已有配置存储是否可直接复用；若存在等价配置，应收敛到该配置而不另建重复来源。

## 七、数据库与文件保护

| 数据或文件 | 目标保护方式 |
| --- | --- |
| `material_prices` | SELECT、INSERT、UPDATE 仅工程师和管理员；不新增业务未要求的删除权限 |
| `pricing_settings` | 仅工程师和管理员读取、更新；初始化由受控脚本完成 |
| `finished_harness_cost_analyses` | 仅工程师和管理员读取；本方案不自动开放原表成本分析编辑 |
| `finished_harness_materials` | 普通读取只含选型信息和允许公开的价格，不含成本及成本原表来源 |
| `cost-analysis-sources` | 保持私有桶，读取和签名 URL 生成仅工程师、管理员允许 |
| 图片和业务图纸 | 保持原有访问规则，实施时检查是否夹带成本或内部定价信息 |

RLS 限制的是行，不能隐藏同一行的成本字段。推荐将成品主表的 `total_cost`、成本原表来源等内部字段收敛至受保护的成本分析表；成品列表和普通详情使用显式字段白名单。不得只删掉前端查询字段而保留业务员对包含成本的原表全列读取权限。

CRM 最低售价、Excel 售价、样品价、建议对外报价含义不同，不互相回填或兜底。目标默认规则为业务员只看到正式对外报价，最低售价和内部参考价格属于内部明细。实施前确认哪个现有价格字段代表正式对外报价；缺失时显示待核价，不擅自把内部价当成对外价。

成本原表使用短有效期签名 URL，不把下载链接写入普通报价响应。角色降级后禁止新下载或新签名请求；已经签发的 URL 可能在过期前仍有效。若验收要求每次下载实时校验角色，则使用认证下载代理，不能依赖签名 URL 实现即时撤销。已合法下载的文件无法通过权限降级收回。

## 八、前端与导出调整

- 用户状态增加角色、权限加载状态及固定能力判断；权限未就绪时，不显示敏感内容也不触发敏感数据请求。
- 覆盖设计器报价面板、现有自动报价入口、物料库列表与详情、价格导入编辑、参数维护、报告复制、Excel 预览及导出。
- 业务员仅加载目录和普通报价结果，移除其完整价格库预加载与本地成本计算。
- 工程师和管理员显示成本明细及价格维护入口；角色分配入口仅管理员可见。
- 对外报价单仅含产品、规格、数量、交期、最终单价和总价，不含成本、毛利、公式、内部价格或隐藏工作表。
- 内部成本分析导出仅使用经授权取得的计算结果。读取来源文件、导出服务接口同样校验权限。
- 账号切换、退出登录或检测到角色变化时，清理价格、成本分析、成本文件链接及内部报价缓存；异步请求结果必须防止回写到新的账号会话。
- 定价维护后重新核价；请求失败时明确显示未获得有效报价，避免继续展示可被误认为有效的旧结果。

## 九、实施顺序

1. 核验现有报价入口、目录中的定价信息、远程 RLS 与 Storage 配置，确认正式对外价格的字段语义。
2. 增加角色存储、授权函数与受保护的角色管理接口，初始化三种角色的测试账号。
3. 建立定价参数的唯一来源，将计算器移至服务端，先通过金额、精度与舍入回归测试。
4. 前端报价统一接入服务端结果，拆分对外报价单与内部成本报告，增加工程师和管理员的定价维护入口。
5. 收敛成品表敏感字段，限制价格、参数、成本分析和成本原表权限，移除业务员敏感预加载。
6. 执行角色越权测试、账号切换测试、导出检查和项目要求的质量门禁，完成数据库与应用配套部署验证。

数据库收紧和前端切换应作为同次测试版本交付，避免业务员因旧前端依赖直接读价格而无法核价。实际远程写入、发布和 Git 操作按实施时的用户授权执行。

## 十、验收与验证

| 验收场景 | 预期结果 |
| --- | --- |
| 业务员填写有效规格并获取报价 | 返回正式单价、总价，金额与基准用例一致 |
| 业务员直接请求价格表、配置、成本分析及成本文件 | 无法读取敏感记录、生成下载链接或下载文件 |
| 业务员直接提交价格导入、更新参数或修改角色 | 被服务端或数据库拒绝，数据不发生变化 |
| 业务员检查网络响应、复制内容、Excel 和缓存 | 无采购价、成本、工时费用、毛利和公式；无隐藏明细表 |
| 工程师查看明细并导入价格、修改定价参数 | 成功；后续报价使用新价格及参数 |
| 工程师修改自己或他人的角色 | 被拒绝 |
| 管理员分配角色及维护价格参数 | 成功；权限与数据变化符合预期 |
| 高权限账号切换到业务员 | 不显示残留明细，旧异步结果不回写到业务员会话 |
| 工程师被降级为业务员 | 后续敏感接口立即拒绝；文件链接按第七节规定处理 |
| 导入包含重复键、无效价格或不存在的物料 | 整批失败，不留下部分更新 |
| 两人同时修改定价参数 | 版本冲突可识别，不静默覆盖 |
| 缺价、超出支持范围、接口失败 | 返回待核价或错误状态，不回退到旧报价或零报价 |
| 页面、复制及导出使用同一计算结果 | 最终金额和内部明细一致 |
| 访问其他用户的项目或图纸 | 仍遵守原有所有者隔离规则 |

验证应使用业务员、工程师、管理员的真实会话分别请求接口与数据库，不能只修改前端状态模拟角色。覆盖物料价格匹配、加工费用、参数边界、金额精度、权限绕过及会话隔离的相关测试。

代码实施后执行项目门禁：针对修改代码执行 `npx eslint <文件路径>`，确保零错误、零告警；执行 `npx tsc -b`；执行 `npm test`。SQL 和 Storage 权限另用实际会话进行集成验证，前端单元测试不能替代数据库权限验证。

## 十一、交付边界

本方案不新增报价审批、历史报价快照、跨用户项目共享、复杂审计平台或动态权限编辑器。若后续要求锁定历史报价、完整追踪每次价格变化或跨用户协作，再按实际需求补充。

已实施：三角色、服务端唯一核价、普通/内部报价响应与 Excel、价格及参数 RLS、单例参数版本控制与 JSON 导入导出、管理员角色分配、成本文件认证下载和业务员单 tab 路由隔离。成品安全视图仅公开 `quote_price`；其余参考价、成本和原表来源按角色脱敏。原有项目所有者隔离继续保留，业务员禁止访问项目和内部图纸。

SQL 顺序与报价函数部署命令见 `supabase/sql/README.md`。首个管理员只能通过可信 SQL 控制台指定准确 UUID 设置；未开放自动提权。角色每 30 秒和窗口聚焦时刷新；数据库每次请求即时判断。已下载文件无法收回。

本地 PostgreSQL 测试覆盖真实 RLS、越权拒绝、参数版本冲突及角色降级。远程真实账号验证、SQL 执行和 Edge Function 部署需要后续完成，当前未执行外部写入。
