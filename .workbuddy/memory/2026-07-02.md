## 重构后修复：localStorage 旧 schema 崩溃

**问题**：用户刷新页面后 `ConfigPanel` 报 `Cannot read properties of undefined (reading 'length')`。
**根因**：localStorage 持久化的旧 config 是 v1/v2 schema（`nodes/wires/connections`），没有 `connectors/materials/protectiveSleeves` 字段，rehydrate 后 `config.connectors` 是 undefined。
**修复**：
1. `harnessStore.ts` 的 persist `merge` 函数：检测 `schemaVersion !== 3` 则丢弃旧数据用默认配置；否则 normalize 补全所有数组字段。
2. `ConfigPanel.tsx` 加可选链防御（`config?.connectors?.length ?? 0`）作为双保险。

### 核心变更
- **删除旧类型**：Wire、Connection、WireBundle、MaterialAttachment、HarnessNode、Branch
- **新增类型**：MaterialCircuit、ConnectorPinRef、ConnectorJumper、ConnectorInstance、ConnectorSide、MaterialEndpoint、JacketUlNumber
- **HarnessConfig** 收敛为 `connectors / materials / protectiveSleeves` 三类业务对象
- **CanvasWireMaterial** 新增 `circuits: MaterialCircuit[]`，PIN/颜色/SIG 下沉到接线明细
- **护套线** 新增可选 `ulNumber`（UL2464 / UL20276）
- **波纹管** 统一显示函数 `getProtectiveSleeveDisplayName`（PA波纹管/PP波纹管/不锈钢波纹管）

### 领域命令（commands.ts）
- `attachMaterialEndpoint` — 单端/多端连接，支持同侧多PIN，拒绝完全重复
- `detachMaterialEndpoint` — 断开接线明细某一侧
- `removeMaterialCircuit` / `updateMaterialCircuit`
- `addConnectorJumper` / `extendConnectorJumper` / `removeConnectorJumper` — 短接
- `getActiveConnectorSide` — 派生连接器有效侧（材料和短接都锁定）

### 画布交互
- HarnessCanvas 统一调用 `attachMaterialEndpoint`，不再创建新线材
- ConnectorNode 按 activeSide 条件渲染 Handle，短接显示橙色标记和侧边条
- WireMaterialNode 信息窗读 `circuits`，未连接侧留空
- 新增 JumperEdge 组件（橙色 smooth-step 边）
- `isValidConnection` 允许同连接器同侧 PIN 互连（短接）

### 删除的文件
- WireEdge.tsx、WireListPanel.tsx、WireTablePanel.tsx、PinMatrixPanel.tsx、ConnectorPinView.tsx、WireModel.tsx

### 用户确认的关键决策
- 无需旧数据迁移（系统开发中）
- SIG 空值用 placeholder 显示，不存储默认值
- 同侧多PIN = 多个独立接线明细
- 短接也锁定连接器有效侧
- 同一 PIN 不允许重复连接完全相同的线材端点
- 护套线多芯颜色沿用固定序列
